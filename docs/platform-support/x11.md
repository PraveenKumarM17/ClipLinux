# X11

X11 is the only session type where ClipLinux registers a **native global
shortcut** in-process.

## Clipboard

Text watch uses XFixes `SelectionNotify` on CLIPBOARD (PRIMARY optional).
See [PLATFORM_CAPABILITIES.md](../../PLATFORM_CAPABILITIES.md).

## Activation (Phase 4A)

When `XDG_SESSION_TYPE=x11` and `[activation.x11] enabled = true`:

- `clipl-daemon` connects to `$DISPLAY`
- Looks up the keycode for the configured key
- Maps Super to the modifier that actually carries `Super_L` / `Super_R`
- Calls `XGrabKey` for that chord plus CapsLock/NumLock/ScrollLock variants
- Waits on X events (`poll_for_event`). It does **not** select `KeyPress` on
  the root window (that would receive every key)
- Unregisters with `XUngrabKey` on shutdown

If grab fails, `clipl status` reports `error` and does not claim the shortcut
is active.

**Never used on Wayland**, including XWayland (`DISPLAY` may still be set).

Default chord: Super+V. Window managers often bind Super+… combinations;
conflicts are reported by X as grab failure or by both clients seeing the key.

## Manual fallback

```
clipl open
clipl toggle
```
